# 抽選ウォッチ（X抽選販売ウォッチャー）

Xで流れる「商品の抽選販売」の告知を自動で集め、スマホで見やすい一覧ページにまとめます。
応募そのものは自分で行います（ボタン1つで応募ページが開きます）。

```
GitHub Actions（2時間ごと）
  ├─ X公式API：監視アカウントの投稿だけを取得（since_idで重複取得なし）
  ├─ ルール判定：懸賞・終了告知を除外、単純な告知は無料で読み取り
  ├─ Claude：複数店舗入りのまとめ投稿や画像の投稿を、店ごとに分解して読み取り
  ├─ 統合：同じ抽選のリマインド・重複を1件に、同じ商品は1枚のカードに
  ├─ ntfy：毎朝のダイジェスト（締切が今日・明日・2〜3日後）と、締切が近い新着をスマホに通知
  └─ GitHub Pages：一覧ページ（スマホ向け）を更新
```

- **ネットで完結する抽選だけ**を載せます。店頭応募・店頭受取・入店抽選・整理券など、店に行く必要がある抽選は収集の段階で除外します（`config/settings.yml` の `items.channels`）。
- 応募済み・スキップ・非表示の記録は**スマホのブラウザ内だけ**に保存します（公開リポジトリには載りません）。
- 公開ページには投稿本文を載せず、読み取った事実（商品・店・締切・条件・URL）と元投稿へのリンクだけを載せます。

## 費用の目安

監視アカウント6つの場合の目安です（2026-11-24〜25 に各アカウントの実際の投稿量を見て見積もり）。

| 項目 | 目安 | 備考 |
|---|---|---|
| X API | 月$5〜7 | 1日40件前後。返ってきた投稿1件ごとに課金（約$0.005/件とされるが、**Developer Consoleの表示が正**）。広告（#PR）と当選発表まとめはX側で除外して課金しない |
| 発見モード（最初の1週間） | 計$2前後 | 1日50件まで（`discover.until` の日付で終了） |
| Claude API（Opus 5.5） | 月$15〜25 | 初回実行（2026-11-24）の実績 約$0.7/日から見積もり。Claudeの有料プランに付くAPIクレジットがあれば、その範囲で足ります |
| Claude API（Haiku 5.5） | 月$1〜2 | 同じ処理をHaikuで行った場合 |
| モデル比較（最初の7日間） | 計$0.5未満 | Opusで読んだ投稿をHaikuにも読ませて比べる（下の「OpusとHaikuの比較」） |
| GitHub / ntfy | 無料 | 公開リポジトリの場合 |

「応募：〜〆 当選：〜 購入：〜」のような整った1件ずつの告知はルールで読み取るためAI費用はかかりません。AIに回るのは主に複数店舗のまとめ投稿です。

安全装置として、1日の取得上限（`daily_post_budget`）とAI呼び出し上限（`max_calls_per_day`）を `config/settings.yml` に設定しています。X・Anthropic双方のコンソールでも**利用上限（spend limit）を必ず設定**してください。

## セットアップ

### 1. GitHubにリポジトリを作ってアップロード
1. GitHubで**公開（Public）リポジトリ**を新規作成（例：`x-lottery-apply`）。README等は追加しない。
2. このフォルダ（コミット済み）で次を実行（`<ユーザー名>` は自分のもの）：
   ```powershell
   git remote add origin https://github.com/<ユーザー名>/x-lottery-apply.git
   git push -u origin main
   ```
3. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする。

### 2. X API（Bearer Token）
1. [X Developer Console](https://developer.x.com/) でアプリを作成。
2. **Bearer Token** をコピー（他人に見せない）。
3. クレジットを購入し、**利用上限**を設定。

### 3. Claude API（APIキー）
1. [Claude Console](https://platform.claude.com/) でAPIキーを発行。
2. クレジットを購入し、**月の利用上限**を設定。

### 4. ntfy（スマホ通知）
1. スマホに **ntfy** アプリを入れる（iOS / Android）。
2. 「+」で購読。トピック名は**推測されにくいランダムな文字列**にする（例：`chusen-7f3k9q2m8x`）。ntfy.shのトピックは名前を知っていれば誰でも読めるため。

### 5. GitHubに鍵を登録
リポジトリの **Settings → Secrets and variables → Actions**

**Secrets**（New repository secret）

| 名前 | 値 |
|---|---|
| `X_BEARER_TOKEN` | XのBearer Token |
| `ANTHROPIC_API_KEY` | ClaudeのAPIキー |
| `NTFY_TOPIC` | ntfyのトピック名 |

**Variables**（任意）

| 名前 | 値 |
|---|---|
| `CLAUDE_MODEL` | 読み取りに使うモデル。未設定なら `claude-opus-5-5` |
| `COMPARE_MODEL` | 比較用モデル。未設定なら `claude-haiku-5-5`（最初の7日間だけ自動で比較） |
| `SITE_URL` | 一覧ページのURL。未設定なら `https://<ユーザー名>.github.io/<リポジトリ名>/` |

### 6. 監視アカウントを確認
`config/accounts.yml` に、実際の投稿を確認して選んだアカウント6つを登録済みです（選んだ理由と、外したアカウント・追加候補もファイル内に記載）。GitHubの画面上でも編集できます。

### 7. 初回実行
**Actions → collect → Run workflow** で手動実行。完了後：
- Actionsのログに「取得 ◯件 / 除外 ◯ / …」と出ていること
- X・Anthropicのコンソールで実際の課金額
- ntfyに通知が届くこと
- スマホで一覧ページが開けること → **共有 → ホーム画面に追加**でアプリのように使えます

以降は日本時間 7〜23時の2時間ごとに自動で動きます。

## 使い方（スマホ）

- **受付中**：締切が近い順。商品ごとのカードに、店ごとの抽選が並びます。
  - **応募ページへ** → 応募 → ページに戻ると「応募しましたか？」と聞かれるので **応募した** をタップ
  - 興味のない抽選は **スキップ**、商品ごと消したいときは **非表示**
  - 各抽選には受取方法の印が付きます。**ネット**＝ネットで完結、**受取方法は要確認**＝投稿に書かれていない（応募ページで確認してください）。
  - 一番下の「要確認」は自動で読み取れなかった投稿です。開いて自分で確認してください。
  - 一番上の「**今日締切／明日締切／2〜3日後**」の数字を押すと、その見出しまで移動します。締切が近い抽選は赤・オレンジ・黄色で目立たせています。
- **応募済み**：当選発表日が近い順。
- **候補アカウント**：発見モードで見つかった、抽選情報をよく流すアカウント。ネット抽選の投稿が多い順に並びます。良さそうなら `accounts.yml` に追加。
- **設定（歯車）**：スキップ／受取方法不明の表示切替、非表示の解除、記録の書き出し／読み込み（機種変更用）、収集状況、監視アカウントの評価。

### 監視アカウントの絞り込み
目標は「**ネット抽選（店頭受取でないもの）を多く、ほかと重複せずに伝えるアカウントだけを、できるだけ少なく**」監視することです。そのために次を自動で集計します（`data/account_log.json`）。

- 直近14日のネット抽選ごとに、どのアカウントが伝えたか。アカウントごとの件数と「単独」（そのアカウントだけが伝えた件数）
- アカウントごとに取得した投稿数（X APIの費用の目安）
- **少ないアカウントで網羅できる組み合わせ**：いちばん多く伝えたアカウントから順に、新しく足せる件数が多いものを選び、網羅率が95%に届いたところまでを「残す」、それ以外を「外す候補」にします

結果は、一覧ページの設定画面（監視アカウント）と、**毎週月曜のダイジェスト**に出ます。「外す候補」が2週続いたら `accounts.yml` から外し、候補アカウントタブの上位と入れ替えて試す、をくり返します。
期間・目標の網羅率・曜日は `config/settings.yml` の `evaluate` で変えられます。

### 通知（ntfy）
- **毎朝7時ごろ（1日1回）**：締切が今日・明日・あさって・3日後の抽選を、日ごとに分けて1通で届けます。今日締切があるときは優先度「高」になり、音とバナーで目立ちます。
- **締切が36時間以内の新着**：見つけた時点ですぐ届けます（翌朝のダイジェストでは間に合わないかもしれないため）。
- それ以外の新着は、翌朝のダイジェストに件数だけ載ります（一覧ページにはすぐ載ります）。
- 応募済みの記録はスマホの中だけにあるため、**通知には応募済みの抽選も含まれます**。一覧ページでは応募済みは表示されません。
- 時刻・日数・すぐ知らせる範囲は `config/settings.yml` の `notify` で変えられます。

## 調整のしかた

| やりたいこと | 場所 |
|---|---|
| 監視アカウントの追加・削除 | `config/accounts.yml` |
| 店舗抽選も載せる | `config/settings.yml` の `items.channels` に `store` を追加 |
| 受取方法の判定に使う語 | `config/keywords.yml` の `store_markers` / `online_markers` |
| 実行間隔 | `.github/workflows/collect.yml` の `cron` |
| 取得上限・AI上限・通知のタイミング・発見モードの期限 | `config/settings.yml` |
| 除外語・ジャンル判定の語 | `config/keywords.yml` |
| 店名の表記ゆれ・公式ドメイン | `config/retailers.yml` |
| AIモデルの切り替え | GitHub Variables の `CLAUDE_MODEL` |

### OpusとHaikuの比較（最初の7日間・自動）
最初の7日間は、Opus 5.5で読み取った投稿をHaiku 5.5にも読ませて結果を比べます（一覧に載るのはOpusの結果です）。設定は不要です。

1. 毎朝のダイジェストに「モデル比較中：claude-haiku-5-5 の一致率 ◯%（◯投稿）」と出ます。比較が終わった日から3日間は「モデル比較が終わりました」と出ます。
2. 詳しくはリポジトリの `data/compare_report.json` を見ます。`diffs` に、結果が食い違った投稿のリンクと両モデルの読み取り結果（店・締切）が入っています。
3. 一致率は「一覧に載る店と締切が完全に一致した投稿の割合」です。まとめ投稿は1件でも食い違うと不一致になるため、厳しめの数字になります。商品名と受取方法の印は比べていません。
4. 判断の目安：一致率がおおむね9割以上で、`diffs` を数件開いてもHaiku側の取りこぼしや締切の誤りが目立たなければ、Variables に `CLAUDE_MODEL = claude-haiku-5-5` を設定して切り替えます（Claudeの費用は月$8〜15 → $1〜2）。Haikuは自動で effort `medium` で動きます（`config/settings.yml` の `effort_by_model`）。
5. 差が大きければOpusのままにします。中間の Sonnet 5.5（費用はOpusの約半分）も試せます。Variables に `COMPARE_MODEL = claude-sonnet-5-5` を設定すると、その日から7日間、Opusと比べます。
6. 同じ組み合わせでもう一度比べたいときは `data/compare_report.json` を削除します。比較をしないなら `config/settings.yml` の `compare_days` を `0` にします。

## 手元での動作確認（課金なし）

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pytest
.venv\Scripts\python -m collector.main --dry-run
.venv\Scripts\python -m collector.main --mode build --dry-run
.venv\Scripts\python -m http.server 8765 --directory _site
```
`--dry-run` は `tests/fixtures` の架空の投稿で動き、API呼び出しも通知もしません。結果は `.dryrun/` に出ます。

## 注意
- フォロー・リポストや外部サイトへの応募を**自動で行う機能はありません**（Xの自動化ルールや各サイトの規約違反、凍結リスクを避けるため）。
- 読み取りは自動のため、締切や条件が間違っている可能性があります。応募前に必ず応募ページで確認してください。
- 公開リポジトリのスケジュール実行は、60日間リポジトリに動きがないと停止されることがあります（このシステムは毎回データをコミットするため通常は止まりません）。
